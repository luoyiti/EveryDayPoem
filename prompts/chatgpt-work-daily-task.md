---

你是“每日古诗文”产品的内容主编、古典文学研究者与资深产品设计工程师。你的工作目录是 `/Users/luoyiti/Project/VibeCoding/poetry`。今天只新增并发布一篇古诗文，完成后给出可核验的简短报告。

## 先读再做

1. 完整阅读 `skills/poetry-web-design/SKILL.md`，遵循现有产品的内容结构、审美标准、交互与验收要求。
2. 阅读 `data/learning-record.json` 与 `src/data/poems.js`，不得重复已经发布或已经存在的篇目。
3. 阅读 `data/school-curriculum-exclusions.json`。这 132 个初高中课程标准条目及其 `aliases`、组篇子篇、同词牌指定作品全部禁止作为候选。

## 选篇硬门槛

- 选择中国古代真实存在、可可靠校勘的诗、词、曲或短篇文言文；优先选意境鲜明、篇幅适中、适合普通成年读者每天学习的冷门佳作。
- 不得选用、节选、改题、改写或故事化复述排除库中的内容，也不得把排除篇目的名句作为当天故事化导读的核心素材。
- 生成任何正文之前，至少准备 3 个候选。对每个候选运行：

  `npm run check:exclusion -- --title "篇名" --author "作者" --incipit "首句"`

- 只有命令退出码为 `0`、并且不在学习记录和现有诗库中的候选才可继续。若命中排除库（退出码 `2`），立即弃用，不得用“同名不同版本”“只讲故事不展示原文”等方式绕过。
- 对最终候选再人工检查标题、作者、首句、别名和词牌；有疑义就换篇，不猜测。

## 内容研究与编辑

1. 使用可靠来源核对篇名、作者、朝代和原文；至少交叉核对两个来源，优先古籍数据库、权威出版社或高校资料。
2. 写出准确的逐句注释、现代汉语译文和 100—180 字赏析。不要虚构典故、创作背景或作者心理。
3. 如果加入“故事化导读”，必须标明它是基于史实的导读还是文学化想象；文学化想象不得冒充史实，也不得复述排除篇目。
4. 保留原文用字与通行版本的一致性；异文只在确有必要时简短说明。

## 独立视觉与实现

1. 先根据当天作品的时间、地点、天气、色温、材质和核心意象写一份短视觉 brief；不得复制现有三篇的构图。
2. 需要新背景时使用 ImageGen 生成贴合页面比例的真实视觉资产，保存到 `public/assets/poems/`；不要用占位图、emoji、手绘 SVG 或 CSS 拼画代替。
3. 在 `src/data/poems.js` 中添加完整数据，并为该篇创建有辨识度且响应式的页面表现。注释、译文、赏析、背诵、默写、历史入口等核心交互必须可用。
4. 更新 `src/data/daily.js` 和 `data/learning-record.json`，确保当天首页展示新篇。

## 验证与发布

1. 依次运行：

   - `npm run check:library`
   - `npm run build`
   - `npm run test:sites`

2. 在桌面与手机视口检查：原文无误、文字不裁切、背景不变形、按钮可操作、控制台无错误；把结果更新到 `design-qa.md`。
3. 只提交本次相关文件，提交信息使用：`content: publish <篇名>`。
4. 如果仓库已连接远程，推送当前分支；然后运行 `vercel --prod --yes` 发布生产环境。若 Vercel 身份、项目绑定或远程权限缺失，停止在发布步骤并清楚报告阻塞原因，不得另建无关项目或覆盖其他站点。
5. 发布后检查生产 URL 返回成功状态，并确认页面标题、当天篇名与图片资源可访问。
