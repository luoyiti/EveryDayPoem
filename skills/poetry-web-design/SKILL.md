# 古诗文网页设计 Skill

每次新增诗篇前先读完本文件。目标不是“把诗放进漂亮模板”，而是找出这首诗不可替代的视觉结构。

## 先理解，再构图

1. 提炼诗的情绪温度：冷/暖、疏/密、动/静、明/暗、近/远。
2. 找出主导感官：画面、声音、触感、时间变化或空间移动。
3. 找出转折点。页面的主交互应回应转折，而不是随手加视差。
4. 用一句视觉命题描述页面，例如：“一声钟穿过江面，读者沿回声逐句进入诗中。”

## 生成式设计要求

- 每首诗必须改变至少三项：空间构图、阅读顺序、内容层级、学习交互、字体比例、图像角色。
- 不允许只换背景、色板或装饰图案。
- 原文永远是第一视觉层级；注释、译文与赏析按需出现。
- 页面先用留白、对齐、字号和节奏分区，再考虑边框或容器。
- 单页最多两套字体。正文优先使用可读性好的宋体/衬线体。
- 长译文每行不超过约 32 个汉字；工具文字不小于 12px。

## 意象到视觉语言

- 声音：用阅读节奏、扩散、延迟和逐句显隐，不要画“声波图标”充数。
- 空旷：用真实负空间与极小主体，不要堆雾、山、月亮等素材。
- 春日：重点放在光、空气、湿度和偶然细节，避免通用粉色花瓣背景。
- 夜色：保留暗部层次，暖色只服务于视线或叙事节点。
- 旅愁：通过距离、遮挡、视角与不可抵达的光表达，不使用伤感文案解释。

## 资产规则

- 诗境图、纹理与插画必须使用真实来源或 ImageGen 独立生成，并放入 `public/assets/poems/`。
- 图片中不写诗文或 UI；文字保持为可访问的 HTML。
- 为文字预留低细节区域，检查桌面与移动裁切。
- UI 图标使用统一图标库，不手绘 SVG，不用 emoji 代替。

## React 落地

- 在 `src/data/poems.js` 添加结构化诗词数据。
- 为新诗写独立页面组件或明确独立布局，禁止无限增加 `theme` 条件来给同一模板换皮。
- 注释、译文、赏析、背诵与默写至少完成一条核心学习路径。
- 键盘焦点、对比度、减少动态效果、移动端换行都必须验证。
- 完成后与目标设计在同一视口截图对比，修复 P0–P2 问题。

## 应避免的 AI 网页习惯

- 居中大卡片、卡片套卡片、所有内容都圆角。
- 玻璃拟态、霓虹渐变、无意义徽章和指标。
- 用小字和低对比度制造“高级感”。
- 把所有功能同时展示在首屏。
- 用通用山水图覆盖诗歌自身的时间、视角和叙事。

## 完成定义

离开背景图后，页面的构图和交互仍能说明这是哪一首诗；打开另一首时，读者能明显感到自己进入了另一个作品，而不是切换了主题。
